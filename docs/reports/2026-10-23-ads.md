# Rewarded ads — implementation report

_23 October 2026_

## Summary

Free players who have used their 3 daily games can now watch a real rewarded ad (Google AdMob) to unlock
one more game. The ad plays when they start the game, and the game starts as soon as the ad ends. Ads
live in a new `ads` module, so the game code never touches Google's SDKs. Everything runs on **Google's
public test IDs**; real IDs go in when the AdMob account exists (see [Pins](#pins-connect-when-accounts-are-ready)).

Tested end to end in the iOS simulator. Android is built and unit-tested but has not been run.

## What the player sees

1. **First launch:** Google's consent form (only in regions that require it, such as the UK and EU), then
   Apple's "Allow tracking?" prompt on iOS. The ads SDK starts and a rewarded ad is preloaded.
2. **Main menu, free games used up:** "Watch an ad to play Guess the country / Guess the flag", plus "Upgrade".
3. **Tap watch:** a short "Loading a short ad…" screen, then the full-screen ad.
4. **Ad watched to the end:** the chosen game starts. One ad unlocks exactly one game.
5. **Ad closed early:** back to the main menu, no game.
6. **No ad available** (offline, no ad to show, consent refused at SDK level): the player gets the game
   anyway, so nobody is ever blocked by Google having no ad. This is one line in `GameViewModel.playAfterAd`
   if you'd rather block instead.

## How it's built

```
ads/                                   new KMP module
  commonMain  AdService, RewardedAdResult (Rewarded / Dismissed / Unavailable)
  androidMain GoogleAdService: UMP consent, Mobile Ads SDK 25.5.0, rewarded load/show
              AndroidManifest.xml: AdMob app ID
  iosMain     NativeRewardedAds (protocol implemented in Swift) + IosAdService (callbacks → coroutines)
shared/                                depends on ads (api) and re-exports it to Swift
  GameViewModel  initialize() at launch; watchAd(mode) → showRewardedAd() → start game / menu
  ui/Screens.kt  AdScreen (shown behind the full-screen ad)
iosApp/
  GoogleRewardedAds.swift  UMP 3.1.0 consent → ATT prompt → Mobile Ads SDK 13.11.0 → rewarded ads
  Info.plist               GADApplicationIdentifier, NSUserTrackingUsageDescription, SKAdNetworkItems
  project.pbxproj          Swift package: googleads/swift-package-manager-google-mobile-ads (13.11.0+)
```

Why a module: ads are the first feature that wraps a third-party SDK with platform-specific code. Keeping it
behind `AdService` means the game is tested with a fake, the SDK can be swapped (e.g. for a mediation
SDK) without touching the game, and in-app purchases and leaderboards can follow the same pattern as their
own modules. The game itself stays one module for now; splitting domain/data/UI further would add build
complexity without a real benefit at this size.

Consent follows Google's rule: ads are requested only when the consent SDK says `canRequestAds`. Google's
test app ID comes with Google's own test consent form, so the full consent flow was exercised with test IDs.

## Pins: connect when accounts are ready

Find them all with `grep -rn "TODO(admob-account)" ads iosApp --exclude-dir=build`.

| # | Where | What to do |
|---|---|---|
| 1 | `ads/src/androidMain/AndroidManifest.xml` | Real Android AdMob **app ID** |
| 2 | `ads/src/androidMain/.../GoogleAdService.kt` (`AdUnitIds`) | Real Android **rewarded ad unit ID** |
| 3 | `iosApp/Info.plist` (`GADApplicationIdentifier`) | Real iOS AdMob **app ID** |
| 4 | `ads/src/iosMain/.../NativeRewardedAds.kt` (`AdUnitIds`) | Real iOS **rewarded ad unit ID** |
| 5 | `iosApp/Info.plist` (`SKAdNetworkItems`) | Paste Google's full SKAdNetwork list |

Account-side, outside the code:

- **AdMob:** create the account, register both apps, create a rewarded ad unit per app.
- **AdMob → Privacy & messaging:** publish a GDPR consent message for both apps. Without it, players in the
  UK/EU won't be shown ads (they'll still get their game).
- **Website:** host `app-ads.txt` on the site listed in both store pages.
- **Store forms:** declare ads and the advertising identifier in App Store privacy labels and Play Data safety.
- **Never tap your own real ads.** Keep test IDs in debug builds, or register your phone as a test device in
  AdMob, otherwise Google can suspend the account.
